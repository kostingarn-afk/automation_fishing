# Proposal

## Why

Исходный бот из статьи 2017 (Python 2, macOS) неработоспособен на текущем окружении, а
актуализированный план (`wowfish-actualization-plan.md`) описан под долгую автономную работу:
аудио-слой, калибровку, анти-детект, сессии. Прежде чем вкладываться в этот объём, нужно дешёвое
доказательство, что базовая схема — захват экрана + `SendInput` без чтения памяти — вообще
применима к клиенту 3.3.5.12340 на этой машине. Неизвестных, которые решают судьбу проекта,
четыре: не отдаёт ли клиент чёрный кадр, принимает ли инъекцию ввода, отделяется ли всплеск
поклёвки от воды, и кликается ли поплавок по найденным координатам.

## What Changes

- Новый каталог `demo/` — 10 файлов Python и `requirements.txt` (~2050 строк), запуск
  `python loop10.py`; рабочие каталоги `trace/` и `fail/` создаются в рантайме.
- Поиск окна клиента: заголовок, класс (`GxWindowClass` / `GxWindowClassD3d`), PID и exe-владелец.
- DPI-aware пересчёт клиентских координат в экранные (`GetClientRect` -> `ClientToScreen`),
  проверка foreground перед каждым кликом.
- Захват клиентской области через `mss`, ROI — доли `X 0.35–0.65`, `Y 0.20–0.50`
  (вертикаль сдвинута в воду: y поплавка ≈ 0.287 высоты клиента).
- Детект поклёвки по **всплеску** (яркий расширяющийся blob в ROI); клик — по подтверждённой
  позиции самого поплавка (`BobberTracker`), потому что центроид пены смещается на 10+ px.
- Верификация исхода: `bobber_present(roi)` после клика, до 3 повторов подсечки.
- Трасса блока из 10 циклов в файл с маркерами `WIN_FAIL` / `LOST` / `MISS` / `NO_STRIKE` / `OK`
  и вердиктом блока (>= 8 `OK`, то есть до 2 осечек); после блока сразу начинается следующий —
  сессия идёт до отмены пользователем.
- Сохранение кадра каждого отказа в `fail/` с номером блока и цикла.
- Аварийный стоп по `F12` и стартовый контракт: отсчёт 5 с, затем пользователь возвращает фокус WoW.
- Одноразовые probe-скрипты (`probe_capture`, `probe_preflight`, `probe_input`, `probe_splash`)
  как проверки предусловий, а не как часть поставляемого кода.

**Не входит в change:** аудио-слой (`soundcard`, корреляция с `FishingBobber_ver2_*.wav`),
калибровка и `config.toml`, CLI (`run / dry-run / calibrate / devices`), пакет `wowfish/`
с `pyproject.toml`, автомат состояний, джиттер, лимиты сессии, анти-детект, автоматические тесты.
Это критерий 2–3 из плана (§7).

## Capabilities

### New Capabilities

- `game-capture`: обнаружение окна клиента, DPI-aware пересчёт клиентских координат в экранные,
  захват ROI кадра, контроль foreground и аварийная остановка.
- `bite-detection`: выделение ярких кластеров в ROI, распознавание всплеска поклёвки,
  проверка присутствия поплавка для верификации исхода.
- `fishing-session`: цикл каст -> ожидание -> подсечка -> верификация, блоки по 10 циклов
  с вердиктом и автоповтором, трасса с маркерами, сохранение кадров отказов.

### Modified Capabilities

Нет: в `openspec/specs/` пока нет ни одной capability, этот change создаёт первые три.

## Impact

- **Новые файлы:** `demo/requirements.txt`, `demo/win.py`, `demo/input.py`, `demo/capture.py`,
  `demo/vision.py`, `demo/loop10.py`, probe-скрипты (`probe_capture`, `probe_preflight`,
  `probe_input`, `probe_splash`) и офлайн-самопроверка `demo/test_blocks.py`; рабочие каталоги
  `trace/`, `fail/` и `probe/<дата>/` создаются в рантайме.
- **Зависимости:** `mss==10.2.*`, `numpy>=2,<3`, `opencv-python==4.14.*`. Сейчас не установлены;
  установка выполняется только по явному разрешению пользователя.
- **Внешние системы:** клиент WoW 3.3.5.12340 (`C:\Games\circle\CircleL`) — окно, фокус, ввод;
  файловая система — трасса и кадры.
- **Не затрагивается:** файлы клиента, память процесса, `AGENTS.md`,
  `wowfish-actualization-plan.md` (остаётся источником требований), `habr-335580-wow-fishing-bot.md`.
- **Предусловия эксплуатации:** клиент запущен и в foreground, персонаж у воды с удочкой,
  `Auto Loot = ON`, `Click-to-move = OFF`, каст-кейбинд проверен pre-flight.
