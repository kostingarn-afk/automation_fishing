# Бот рыбалки для WoW 3.3.5a — демо

Демонстрационный бот, который ловит рыбу в **World of Warcraft 3.3.5.12340 (Wrath of the Lich King)**
без участия человека: делает заброс, ждёт поклёвку, подсекает и проверяет результат. Затем повторяет
это блоками по 10 циклов, пока вы не остановите его клавишей `F12`.

Работает как **внешняя автоматизация**: смотрит на экран (снимки окна игры) и двигает мышь
через системный ввод. Внутрь процесса игры не лезет — память не читает, DLL не внедряет,
хуков не ставит.

> **Статус:** авто-калибровка и прыжок после поимки приняты живой сессией 06.11.2026: калибровка
> набрала 8 `OK` за 8 циклов, первый блок — «принято» (8 `OK` из 10, прыжок в цикле 9).
> Перспектива — [`wowfish-actualization-plan.md`](./wowfish-actualization-plan.md).

## 1. Что делает бот

1. **Калибровка** (в начале каждой сессии) — по кадру клиента находит воду, ищет поплавок по всей
   её площади и выполняет циклы до **8 `OK`**; по ним уточняются цвет поплавка и пороги всплеска.
2. **Заброс** — нажимает клавишу каста (`1`) и ждёт появления поплавка в кадре (до 4 с).
3. **Ожидание поклёвки** — 20 раз в секунду снимает область и следит за локальным всплеском
   яркости вокруг кандидатов (пена от поклёвки).
4. **Подсечка** — плавно переводит курсор на поплавок (100–300 мс), выдерживает 150–250 мс,
   нажимает правую кнопку с удержанием 60–200 мс.
5. **Проверка исхода** — ждёт 1.2–2.5 с (автолут забирает добычу) и смотрит, исчез ли поплавок;
   если нет — повторяет подсечку, всего до 3 попыток.
6. **Блок** — 10 циклов, затем вердикт и сразу следующий блок. В одном случайном цикле (3–10)
   выполняется прыжок.

`OK` означает **«клик зарегистрирован»**, а не «рыба поймана»: улов по картинке не проверяется.

## 2. Требования

| Что | Значение |
|---|---|
| ОС | Windows (проверено на 1920x1080, DPI 96 / 100 %) |
| Python | 3.12+ (проверено на 3.12.2) |
| Игра | WoW 3.3.5.12340, клиент в оконном maximized режиме |
| Путь к клиенту | `C:\Games\circle\CircleL` (зафиксирован в [`AGENTS.md`](./AGENTS.md)) |

**Настройки в игре (обязательно):**

- **Auto Loot = ON** — иначе окно добычи висит и следующий цикл не начнётся;
- **Click-to-move = OFF** — иначе клик по земле уводит персонажа;
- клавиша каста — `1` (`CAST_KEY` в `demo/loop10.py`);
- **`Space` привязан к прыжку** (`JUMP_KEY` / `KEY_NAMES` в `demo/input.py`);
- окно игры **в фокусе**: без фокуса клиент не принимает ни ввод, ни звук;
- персонаж стоит у воды с удочкой; камеру подгонять не нужно — область поиска вычисляется по воде.

## 3. Установка


## 4. Быстрый старт

Команды §4–§9.5 запускаются **из каталога `demo`** — модули импортируются локально.

```bash
cd demo
python test_blocks.py                 # самопроверка логики, игра не нужна
python loop10.py --countdown 60       # прогон: отсчёт 60 с, затем калибровка и блоки
```

1. Бот проверяет окно, печатает область по воде и запускает отсчёт
   (`старт через 60 с — переключитесь в окно...`).
2. **Переключитесь в игру и не трогайте мышь и клавиатуру** — бот сам двигает курсор.
3. Идут циклы; после 10-го — итог блока и сразу следующий блок.
4. **`F12` — остановка**: текущий блок помечается «прерван», трасса сохраняется, подводится итог.

Коды выхода: `0` — проваленных блоков нет, `1` — был блок «не принято» или авария, `2` — окно
не найдено, фокус не в клиенте, неверные аргументы или отмена `F12` на отсчёте (штатно).

## 5. Режимы запуска

| Режим | Команда | Что делает | Нужна игра? |
|---|---|---|---|
| **Прогон** | `python loop10.py --countdown 60` | калибровка + блоки по 10 циклов до `F12`, трассы и кадры отказов | да |
| **Самопроверка** | `python test_blocks.py` | 25 сценариев логики без клиента: вода, область, кандидаты, калибровка, прыжок, вердикты, коды выхода | нет |
| Окно и захват | `python probe_capture.py` | окна, класс/PID/exe, размер клиента, PNG полного кадра | да |
| Предусловия | `python probe_preflight.py [cast_key]` | отсчёт 5 с, фокус, один каст, изменение ROI после каста | да |
| Ввод | `python probe_input.py [cast_key] [--countdown N]` | до двух циклов (`SendInput` / `mouse_event`), выход после первого `OK` | да |
| Запись каналов | `python probe_splash.py [--repeat N] [--seconds 20] [--key 1] [--countdown N]` | кастует и пишет кадры ROI в `probe/<дата>/frames/` | да |
| Подбор порога | `python probe_splash.py --tune <каталог> [--tune ...]` | офлайн-разбор записей, `tuning_report.md` | нет |

Отсчёт по умолчанию 5 с (`win.START_COUNTDOWN`); для ручного запуска — `--countdown 30–60`.
Полная проверка аргументов есть только в `loop10.py` (ошибка — код `2`); у probe-скриптов свои коды
(см. docstring модуля: например, `7` у preflight — «сцена после каста не изменилась»).

## 6. Что считается успехом

Блок — 10 циклов. Блок **принят**, если в нём не меньше 8 `OK` (допустимо до 2 осечек) и не было
отказа слоя окна.

| Маркер | Слой | Что значит |
|---|---|---|
| `OK` | — | клик дошёл, поплавок исчез |
| `LOST` | зрение | поплавок виден, но всплеск не поймали (или рыба сошла без поклёвки) |
| `MISS` | каст / область | каст не прошёл либо поплавок не попал в кадр |
| `NO_STRIKE` | ввод | всплеск был, но после 3 подсечек поплавок не исчез |
| `WIN_FAIL` | окно / захват | игра не в фокусе или кадр не получен — блок провален, сессия стоп |

`F12` блок не проваливает: он помечается «прерван» и в итог не входит. В каждом блоке один цикл —
случайный из 3–10 — закрывается прыжком (пауза 1–1.5 с, `Space`, ещё пауза); прыжок не меняет
маркер и вердикт.

Калибровка — не блок: её циклы пишутся в отдельную трассу, вердикт не считается, прыжок
не выполняется. Если 8 `OK` не набраны за 25 циклов, сессия продолжается на значениях по умолчанию.

## 7. Артефакты прогона

| Что | Где |
|---|---|
| Трасса блока | `trace/run_<дата-время>_b<NN>.txt` — одна строка на цикл |
| Трасса калибровки | `trace/calibration_<дата-время>.txt` |
| Отчёт калибровки | `trace/calibration_<дата-время>_report.md` — параметры, циклы, маркеры, область воды |
| Кадры отказов | `fail/b<NN>_cycle<CC>_<мс>_<МАРКЕР>.png` |
| Записи каналов | `probe/<YYYYMMDD-HHMMSS>/frames/frame_*.png` + `tuning_report.md` |

Пути от корня; из `demo` это `../trace/…`, `../fail/…`, `../probe/…`.

Формат строки трассы (8 колонок, разделитель ` | `):

```
#05 | cast 0 | burst - | strike - | gone - | jump - | LOST | NO_BURST@11921
#07 | cast 0 | burst 8321 | strike 8942 | gone 11203 | jump 12480 | OK | -
```

| Колонка | Смысл |
|---|---|
| `#NN` | номер цикла внутри блока |
| `cast` | момент каста в мс от начала цикла (всегда 0) |
| `burst` | момент всплеска, мс |
| `strike` | момент подсечки, мс |
| `gone` | момент подтверждения исхода, мс |
| `jump` | момент нажатия прыжка, мс; `-`, если прыжка не было |
| маркер | ровно один из `OK`/`LOST`/`MISS`/`NO_STRIKE`/`WIN_FAIL` |
| причина | `-` для успеха или токен с моментом: `NO_BOBBER@4012`, `NO_BURST@11921`, `TIMEOUT@22005`, `NO_CONFIRM`, `INPUT_BLOCKED@15`, `CAPTURE@…` |

Трассы до появления прыжка содержат 7 колонок — различие видно по числу разделителей.

Сводка (PowerShell, из корня): `(Get-ChildItem trace\run_*.txt | Get-Content | Select-String '\| OK \|').Count`

**Где какие константы:**

| Что | Где | Значение |
|---|---|---|
| Область интереса (фолбэк) | `demo/win.py` → `ROI_FRACTION_X/Y` | X `0.35–0.65`, Y `0.20–0.50` — когда вода не найдена |
| Вода на кадре | `demo/vision.py` → `WATER_*` | H 70–115, S ≥ 50, V 25–215; мутная — доминирующая полоса тона (S ≥ 40, ≥ 25 % кадра) |
| Область по воде | `demo/vision.py` → `WATER_MIN_FRACTION`, `WATER_MIN_SIDE_FRACTION`, `WATER_MARGIN` | ≥ 10 % кадра, стороны ≥ 20 %, отступ 8 px |
| Зона сессии | `demo/loop10.py` → `SCENE_SAFE_X/Y` | X 2–98 %, Y 2–74 % клиента |
| Кандидат в поплавок | `demo/vision.py` → `WATER_AROUND_SHARE`, `WATER_SIMILARITY_SAT/VAL`, `WATER_AROUND_RING` | ≥ 75 % «водных» пикселей в кольце; пределы — 1.35 × медианы S и 1.45 × медианы V; кольцо 10 px |
| Калибровка | `demo/loop10.py` → `CALIBRATION_TARGET_OK`, `CALIBRATION_MAX_CYCLES`, `SEARCH_PRESET` | 8 `OK` / 25 циклов / H ≤ 15, S ≥ 140, V ≥ 25, area 40–400 |
| Захват | `demo/loop10.py` → `ACQUIRE_DELAY`, `MONITOR_LIMIT`, `MONITOR_MATCH_RADIUS`, `BobberTracker.RECENT_FRAMES` | окна с 0.9 с, до 6 окон, кандидат живёт 10 кадров |
| Всплеск | `demo/loop10.py` → `BURST_THRESHOLD`, `SPLASH_RISE`, `WINDOW_PADDING`; `demo/vision.py` → `BURST_VALUE_RATIO`, `SPLASH_RISE_RATIO` | 130 / 18 / +6 px; калибровка: порог = 1.5 × медианы V воды, окно = диаметр + 6; второе условие — 1.15 × база |
| Таймауты и окно | `demo/loop10.py` → `BITE_TIMEOUT`, `ACQUIRE_TIMEOUT`, `GONE_WITHOUT_BURST_FRAMES`, `VERIFY_WINDOW` | 22 с / 4 с / 30 кадров / 1.2–2.5 с |
| Подсечка | `demo/input.py` → `STRIKE_DELAY`, `CLICK_HOLD`, `MOVE_DURATION` | 0.15–0.25 / 0.06–0.20 / 0.10–0.30 с |
| Прыжок | `demo/input.py` → `JUMP_KEY`, `KEY_HOLD`; `demo/loop10.py` → `JUMP_CYCLES`, `JUMP_PAUSE_*` | `space`, 0.06–0.12 с; цикл 3–10, паузы 1–1.5 с |
| Блок и вердикт | `demo/loop10.py` → `BLOCK_CYCLES`, `OK_REQUIRED` | 10 / 8 |
| Признаки поплавка | `demo/vision.py` → `TRACK_*` (по умолчанию), `BOBBER_*` (проверка) | `H≤12, S≥170, V≥105, area 12–200`; проверка — мягкая |

## 9. Отладка

### 9.1. Сначала по маркеру

| Что видите | Куда смотреть | Что делать |
|---|---|---|
| `WIN_FAIL`, игра в фокусе | `probe_capture.py` | окно не найдено или кадр чёрный |
| `WIN_FAIL`, «активно окно …» | консоль | фокус перехватило другое окно — закройте и перезапустите |
| Много `MISS` (`NO_BOBBER`) | `fail/b*_MISS.png` | каст не прошёл (клавиша, удочка) либо поплавок вне области (9.3) |
| Много `LOST` (`NO_BURST`) | `fail/b*_LOST.png` | всплеск не ловится: сцена/порог (9.4) |
| `NO_STRIKE` | `fail/b*_NO_STRIKE.png` | клик мимо: поплавок сместился, окно уехало, ввод блокируется |
| `OK`, но рыбы нет | — | норма: `OK` = клик, рыба может сойти |
| Нет строки «прыжок в …» | консоль | `InputBlocked` перед прыжком — верните фокус игре |
| `MISS` в цикле сразу после прыжка | `fail/b*_MISS.png` | поднимите нижнюю границу `JUMP_PAUSE_AFTER` до 1.1–1.2 с |
| «вода не найдена» | полный кадр | вода не в кадре или её цвет вне `WATER_*`; сессия идёт на фолбэке |
| Калибровка не набрала 8 `OK` | `trace/calibration_*_report.md`, `fail/` | `NO_BOBBER` — поплавок не находится, `LOST` — всплеск не ловится, `NO_STRIKE` — клик мимо |
| В логе база ярких пикселей ~5000 | отчёт калибровки | порог ниже яркости воды — окно насыщено; проверьте `burst_threshold` в параметрах |

### 9.2. Полезные приёмы

- **Не трогайте мышь** во время прогона: бот двигает курсор, ваши движения ломают цикл.
- Один цикл — `probe_input.py --countdown 20`: печатает каждую фазу, выходит после первого `OK`.
- Кадры отказов читайте глазами: это ровно то, что «видел» бот.
- Консоль падает на кириллице — запускайте из UTF-8-терминала (Windows Terminal, PowerShell 7).

### 9.3. Поплавок не попадает в кадр

1. При старте печатается `вода найдена: область …` — это и есть область поиска; камеру подгонять
   не нужно. Область обрезается до зоны без панелей действий и персонажа (`SCENE_SAFE_*`).
2. Если вода не найдена — посмотрите полный кадр: `probe_capture.py` сохраняет
   `probe/<дата>/capture_client.png` (записи `probe_splash.py` уже обрезаны и для этого не годятся).
3. Систематическое «вода не найдена» — правьте пределы `WATER_*` (§8): сначала расширьте
   `WATER_HUE_RANGE`, затем снизьте `WATER_SATURATION_MIN` и `WATER_VALUE_RANGE`.
4. Кандидатом считается только кластер, окружённый водой: доспех и берег отсекаются автоматически.
   Остаётся риск персонажа, стоящего по колено в воде, — сделайте шаг назад или разверните камеру.

### 9.4. Новое место, другой персонаж или освещение

Калибровка подстраивает цвет поплавка и пороги всплеска сама — трогать константы обычно не нужно.
Ручной подбор остаётся для разбора упорных случаев:

```bash
# из demo
python probe_capture.py                       # окно, клиент, DPI
python probe_preflight.py                     # фокус и каст
python probe_input.py --countdown 20          # клик реально убирает поплавок
python probe_splash.py --repeat 6 --countdown 30       # запись сцены
python probe_splash.py --tune ../probe/<дата1> --tune ../probe/<дата2>   # офлайн-подбор
```

Что смотреть: точки поплавка в консоли подбора (должны совпадать с кадрами), таблицу
`порог × прирост` (нужен набор ≥5 всплесков и 0 одиночных) и «Выбор» в `tuning_report.md`.
Всплеск засчитывается при двух условиях: прирост ≥ `SPLASH_RISE` **и** значение ≥ 1.15 × база
(`SPLASH_RISE_RATIO`). Если поплавок другого цвета — правьте `TRACK_*`, но мягкие `BOBBER_*`
(проверка исхода) трогать не нужно.

### 9.5. Проверка после правок

```bash
cd demo && python test_blocks.py          # логика блоков, игра не нужна
cd .. && python -m compileall -q demo     # синтаксис всех модулей
openspec validate --all --strict          # спеки и change
```

Живой блок нужен только при изменениях детекции и таймингов; это **ввод в игру** (~3 минуты,
мышь не трогать), поэтому запускается отдельно от проверок выше.

## 10. Известные ограничения

- **Вторая подсечка — норма.** В большинстве циклов первый клик не подтверждается за 1.2–2.5 с.
- **Чужое окно обрывает сессию.** Любой всплывший поверх игры процесс даёт `WIN_FAIL`.
- **Сцена чувствительна к воде.** Пределы `WATER_*` подобраны по тёмной и дневной воде; мутная
  или красноватая вода может потребовать правки констант (9.3–9.4).
- **Демо, а не инструмент.** Нет аудио-слоя, лимитов сессии, анти-детекта, полноценного CLI.
- **EULA.** Автоматизация нарушает правила игры: риск блокировки аккаунта не снимается ничем.

## 13. Работа с git

Репозиторий: `origin` → <https://github.com/kostingarn-afk/automation_fishing>, ветка `main`.

- **В git:** `demo/`, `openspec/`, документация. **Не попадают:** `__pycache__/`, `trace/`, `fail/`,
  `probe/`, `.opencode/` — артефакты прогонов содержат скриншоты игры и в историю не идут.
- **`.gitattributes` держит LF.** Без него `core.autocrlf=true` даёт ложные диффы по всем строкам;
  лечится `git add --renormalize .`.
- **Отправка:** `git push -u origin main` по SSH (`~/.ssh/id_ed25519`, без пароля). Переезд:
  `ssh-keygen -t ed25519 -C "msi@work"`, `ssh-keyscan -t ed25519 github.com >> ~/.ssh/known_hosts`
  (отпечаток `SHA256:+DiY3wvvV6TuJJhbpZisF/zLDA0zPMSvHdkr4UvCOqU`), публичный ключ — в GitHub →
  Settings → SSH keys; проверка `ssh -T git@github.com`.
